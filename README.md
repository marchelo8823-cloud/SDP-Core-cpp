# Ядро СДП

Ядро системы динамического позиционирования: удержание судна в заданной точке и на заданном курсе по данным внешних датчиков с управлением движителями. В проекте только математическая модель и то, без чего она не работает. Данные судна вводятся в книгу Excel.

Это новый проект, собранный из прежнего (версия 0.28). Прежний проект сохранён отдельным архивом и не менялся.

## Что входит

| Часть | Файлы в `include/dp` |
|---|---|
| Модель судна: корпус, ветер, течение, волна | `model`, `types`, `math` |
| Оценка состояния: слияние датчиков, отбраковка, качка и волнение | `estimator`, `waves`, `calibration` |
| Регулятор (ПИД, LQR, MPC), опорная траектория | `control`, `predict`, `forecast` |
| Распределение упоров по движителям | `thrust` |
| Шаг ядра и его тревоги | `engine`, `alarms` |
| Расчёт возможностей удержания | `capability` |
| Приём датчиков: NMEA по UDP, TCP, COM-порту | `hub`, `nmea`, `telegrams`, `io` |
| Выдача команд движителям: Modbus TCP и RTU | `output`, `modbus` |
| Имитатор судна, среды и датчиков | `sim`, `simfeed` |
| Ввод данных судна и имитатора из Excel, проверка | `shipbook`, `xlsx`, `zipread`, `profile`, `config`, `vesselio`, `json` |
| Рабочий цикл, состояния, команды | `core` |
| Для редактора: запись книги, чертёж и площади, контур, запрос Claude | `xlsxwrite`, `shipdesign`, `contour`, `vision` |

Всего 29 файлов, около 7 тысяч строк. Внешних библиотек нет.

## Что убрано по сравнению с версией 0.28

Окно оператора (HMI), сеть операторских постов и права, администрирование, электростанция (шины, генераторы, ограничение по мощности), словарь сообщений и светофор ASOG, морские карты, запись обмена, связь с чужой СДП, помощник.

⚠ Следствия:
- ограничения упора по мощности электростанции нет: ядро считает, что мощности хватает;
- окна нет: управление командами в консоли, состояние строкой и в журнале CSV;
- часть команд прежнего ядра не перенесена (веса и режимы систем положения, радиус удержания, предел курса, калибровка, движение по маршруту). Сами алгоритмы в ядре остались, нет только команд к ним.

## Порядок работы

Ядро запускается без данных и само ждёт их по очереди. Состояние видно в строке состояния и сообщениях:

| Состояние | Что значит | Что делать |
|---|---|---|
| НЕТ СУДНА | данные судна не загружены | `ship load Данные_судна.xlsx` |
| ЖДУ ДАТЧИКИ | судно загружено, нет курса или положения | дождаться датчиков судна или запустить имитатор |
| ГОТОВ | данные есть, режим ожидания | `thr_take all`, затем `position` или `heading` |
| УДЕРЖАНИЕ | режим курса или позиции | |

- Загруженное судно — основа для модели, оценки состояния, регулятора и распределения упоров.
- Загрузить другое судно можно только в ожидании. Если в новой книге ошибки, остаётся прежнее судно.
- Судно не запоминается: после перезапуска ядро снова в состоянии НЕТ СУДНА.
- При потере всех систем положения во время удержания ядро продолжает держать по счислению с тревогой `POS_DROPOUT` и само режим не снимает.

## Имитатор

Запускается отдельной командой и своей книгой, после загрузки судна и только в ожидании:

```
sim start Данные_имитатора.xlsx
sim stop
```

- Книга имитатора — лист «Имитатор»: ветер, течение, волна, начальный курс, ускорение, порывистость.
- Судно, движители и состав датчиков имитатор берёт из загруженной книги судна.
- Пока имитатор работает, датчики судна не читаются и команды на контроллер не выдаются.
- После запуска или остановки имитатора движители нужно взять заново (`thr_take all`).

## Ввод данных судна

1. Возьмите `data/Данные_судна_шаблон.xlsx` (заполненный образец — `data/Данные_судна_пример.xlsx`).
2. Заполните листы «Корпус», «Движители», «Датчики»; лист «Выдача» — когда есть контроллер движителей.
3. Чтобы датчик давал данные с судна, заполните у него «Подключение» (udp, tcp или serial) и порт или устройство. Без подключения датчик используется только имитатором.
4. Проверьте без запуска ядра: `sdp_run --check Данные_судна.xlsx`, или в работающем ядре: `ship check Данные_судна.xlsx`.

Правила:
- жёлтые ячейки обязательны. Пока хоть одна пуста, судно не загружается, а ядро называет лист, строку и столбец;
- зелёные ячейки необязательны. Если пусто, берётся значение по умолчанию, проверка это перечисляет;
- заглушек нет: ядро не подставляет размеры, упоры и места установки;
- подписи в столбце A и заголовки таблиц менять нельзя: данные ищутся по ним;
- единицы в книге — т, кН, кВт, %/с, градусы; десятичный знак — запятая или точка.

После заполненности проверяется физическая согласованность (движитель вне корпуса, упор на киловатт вне разумных пределов и т. п.) и выдаются оценки: масса по размерам, предельные усилия комплекса, предельный ветер.

## Сборка и запуск

```
cmake -S . -B build
cmake --build build -j
cd build && ctest
./sdp_run
```

Параметры `sdp_run`: `--check <книга судна>` (только проверка), `--log <файл.csv>` (журнал), `--hz <Гц>` (частота цикла, по умолчанию 10), `--duration <с>`, `--status <с>` (период строки состояния), `--quiet`, `--script <файл>` (команды из файла; строка `wait <с>` — пауза).

## Команды

| Команда | Действие |
|---|---|
| `ship load <книга>`, `ship check <книга>`, `ship show` | загрузить, проверить, показать данные судна |
| `sim start <книга>`, `sim stop` | запустить и остановить имитатор |
| `sim wind\|current\|wave\|off\|on\|thr\|jump\|freeze\|fbfault\|noise\|gyro\|mru\|reset` | управление имитатором |
| `thr_take <id\|all>`, `thr_release <id\|all>` | взять движитель под управление или снять |
| `standby`, `heading`, `position` | ожидание, удержание курса, удержание позиции и курса |
| `set <север м> <восток м> <курс °>` | задать точку и курс |
| `move <dС м> <dВ м> [dКурс °]` | сдвинуть точку |
| `hdg <курс °>` | задать курс |
| `pivot <вдоль м> <поперёк м>` | центр вращения |
| `rate rot <°/мин>\|off`, `rate speed <уз>\|off` | предел скорости поворота и перемещения |
| `law pid\|lqr\|mpc`, `gain high\|low` | закон управления и усиление |
| `cap [течение м/с]` | возможности удержания: предельный ветер по сценариям отказов |
| `status`, `help`, `quit` | |


## Редактор данных судна `sdp_ship` (Qt 6)

Отдельная программа для ввода данных судна: те же таблицы, что в книге Excel, и чертёж из простых фигур. Сохраняет ту же книгу `Данные_судна.xlsx`, которую загружает ядро (`ship load`). Ядро от редактора не зависит.

**Вкладки:** «Корпус», «Вид сверху», «Вид сбоку», «Вид спереди», «Движители», «Датчики», «Выдача», «Проверка».

**Чертёж.** Три вида в метрах (X от миделя, + к носу; Y от ДП, + на правый борт; высота над ватерлинией). Фигуры — прямоугольники и многоугольники; их можно двигать, тянуть за вершины, двойной щелчок по стороне добавляет вершину, Delete удаляет фигуру. Колесо — масштаб, правая кнопка — сдвиг вида.

По фигурам считается («По чертежу» → «Перенести в корпус»):
- сверху — длина, ширина, полнота ватерлинии;
- сбоку — всё выше ватерлинии даёт боковую парусность и её центр, ниже — подводную площадь и осадку;
- спереди — лобовую парусность.
Перекрытия фигур считаются один раз.

На виде сверху движители (●) и датчики (■) из таблиц показаны метками; перетаскивание метки меняет X и Y в таблице. Z датчиков — в таблице.

**Схема по данным корпуса.** Пока вы вводите числа на вкладке «Корпус», виды сами показывают то, что из них следует (зелёный пунктир):
- сверху — корпус по длине и ширине, нос клином подобран под полноту ватерлинии (если пусто — 0,8);
- сбоку — подводная часть по длине и осадке (срез днища к носу подобран под подводную площадь, если пусто — 0,85·L·T), надводный блок площадью боковой парусности с центром в заданном месте, движители у днища по своему X;
- спереди — подводная часть по ширине и осадке и надводный блок площадью лобовой парусности.
Схема в расчёт «По чертежу» не входит. Галочка «Показывать» скрывает её, «Сделать фигурами» превращает в обычные фигуры для правки. ⚠ Надводная часть на схеме — условный блок нужной площади, а не форма судна.

**Фото и чертежи.**
1. «Загрузить картинку…» — PNG, JPG, BMP, GIF, TIFF. ⚠ PDF не открывается: сохраните страницу как картинку.
2. «Привязать (2 точки)» — щёлкнуть две точки с известными координатами (например, перпендикуляры на ватерлинии) и ввести их координаты. Привязка учитывает масштаб и поворот.
3. «Контур по картинке» — обвести рамкой предмет: программа предложит контур (порог яркости, тонкие линии вроде ватерлинии и размеров отбрасываются). ⚠ Острые углы немного скругляются; на фото с тенями и перспективой контур нужно править.
4. «Распознать (Claude)» — картинка отправляется в Anthropic API, Claude возвращает простые фигуры и подписанные на чертеже размеры (их можно перенести в корпус). Нужны интернет и ключ API («Распознавание Claude…» на панели; ключ хранится в защищённом хранилище системы: «Связка ключей» macOS, «Диспетчер учётных данных» Windows, Secret Service в Linux; если хранилища нет — только до закрытия программы). ⚠ Это подсказка, результат нужно проверить.

**Хранение.** Фигуры и привязка подложек хранятся в книге на скрытом листе «Рисунок»; сами картинки — нет, только путь относительно книги. Храните картинки рядом с книгой.

**Проверка.** «Проверить ядром» — та же проверка, что при `ship load`: ошибки, предупреждения, значения по умолчанию, оценки.

Сборка: `cmake -S . -B build -DSDP_BUILD_EDITOR=ON`, на Mac с Homebrew добавьте `-DCMAKE_PREFIX_PATH=$(brew --prefix qt)`. Запуск: `./build/shipedit/sdp_ship [книга.xlsx]`.

Образец: `data/чертёж/Данные_судна_с_чертежом.xlsx` с картинками рядом (условное судно, нарисованное для проверки).

## Тесты

23 теста: модель и регулятор (11), возможности судна (`capability_test`), приём датчиков (5), основа редактора (`design_test`: площади, запись книги и её загрузка ядром, контур, разбор ответа Claude), рабочий цикл (`core_test`: запуск без данных, загрузка судна, ожидание датчиков, имитатор, удержание и отказы), чтение и проверка книг судна и имитатора (`shipbook_test`), сценарии рабочей программы (`сценарий_удержание`, `сценарий_отказы`, `сценарий_потеря_курса`).

Сценарий в `tests/scenarios/` — список команд `sdp_run` и критерии в строках `#! ...`, которые проверяет `tests/run_scenario.cmake`:
`#! есть: <текст>`, `#! нет: <текст>`, `#! итог_положение < <м>`, `#! итог_курс < <°>`. Новый файл сценария сам попадает в тесты.

Книги с намеренными ошибками для теста лежат в `tests/books`; заново их делает `tools/make_test_books.py`, шаблон и пример — `tools/make_template.py` (нужен Python с пакетом openpyxl; самому ядру Python не нужен).

## Ограничения

- ⚠ Проверено только в имитаторе на Linux. На Mac, Windows и с настоящими датчиками и контроллером не проверялось.
- ⚠ Книги, сохранённые самим Excel, не проверялись; проверены книги из openpyxl и LibreOffice.
- ⚠ В имитаторе места установки лазерной системы и натянутого троса заданы в коде, а не берутся с листа «Датчики».
- ⚠ Рули, четыре шины и измеренная мощность движителей не моделируются.

## Потеря положения и курса
| Что пропало | Что делает ядро |
|---|---|
| все системы положения | удержание по модели (счисление), тревога POS_ALL_REJ, через 20 с POS_DROPOUT с погрешностью положения по фильтру; уставка оператора не меняется |
| …и вернулись | если судно дальше 2 м от заданной точки — плавный возврат не быстрее 0,2 м/с, тревога POS_RETURN до прихода в точку |
| все гирокомпасы | 30 с: тревога HDG_DR, курс считается последним измеренным, момент по курсу держится средним за 10 с до потери; затем HDG_LOST и нулевой упор |

Настройки (в данных судна, необязательные): `hdgDeadReckonS` (30 с), `returnSpeedMS` (0,2 м/с), `returnStartM` (2 м), `deadReckonMaxS` (0 — счисление положения без ограничения).
⚠ Погрешность положения по фильтру — оценка с большим запасом: в имитаторе она в 4–10 раз больше настоящего ухода судна.
