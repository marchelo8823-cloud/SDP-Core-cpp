# Ядро СДП — запуск

## Сборка
```
cd ~/Downloads
unzip -o SDP-Yadro-v1.3-source.zip
cd sdpcore
cmake -S . -B build
cmake --build build -j
cd build && ctest
```
Должно пройти 22 теста (вместе с двумя сценариями имитатора). Нужны CMake 3.16+ и компилятор C++17, внешних библиотек нет.

## Редактор данных судна (нужен Qt 6)
На Mac один раз: `brew install qt`. Затем из папки `sdpcore`:
```
cmake -S . -B build -DSDP_BUILD_EDITOR=ON -DCMAKE_PREFIX_PATH=$(brew --prefix qt)
cmake --build build -j
./build/shipedit/sdp_ship data/чертёж/Данные_судна_с_чертежом.xlsx
```
- Вкладки «Вид сверху / сбоку / спереди»: загрузить картинку, привязать двумя точками, обвести фигуры вручную или «Контур по картинке», затем «Перенести в корпус».
- «Распознать (Claude)» — нужен интернет и ключ Anthropic API (вводится в «Распознавание Claude…»; хранится в «Связке ключей» macOS или «Диспетчере учётных данных» Windows, открытым текстом не сохраняется).
- «Проверить ядром» — та же проверка, что `ship load`.
- «Сохранить» — книга `.xlsx`, которую потом загружает ядро. Картинки держите рядом с книгой.

## Запуск ядра
Из папки `build`:
```
./sdp_run
```
Ядро запускается без данных и пишет: «Состояние: НЕТ СУДНА».

## Работа с имитатором
Команды с клавиатуры, по очереди:
```
ship load ../data/Данные_судна_пример.xlsx
sim start ../data/Данные_имитатора_пример.xlsx
thr_take all
position
status
move 10 0
hdg 45
sim wind 15 90
sim thr off BOW1
standby
sim stop
quit
```
После `ship load` ядро пишет «ЖДУ ДАТЧИКИ», после `sim start` через несколько секунд — «ГОТОВ».

## Работа с датчиками судна
1. В книге судна на листе «Датчики» заполните «Подключение» (udp, tcp или serial) и порт или устройство.
2. Если есть контроллер движителей, заполните лист «Выдача».
3. `./sdp_run`, затем `ship load Данные_судна.xlsx`. Когда пойдут курс и положение — «ГОТОВ».

## Проверка своей книги
```
./sdp_run --check ../data/Данные_судна.xlsx
```
- «ОШИБКА» — судно не загрузится, исправьте названную ячейку;
- «По умолчанию» — пустая необязательная ячейка и что принято вместо неё;
- «Оценка» — расчёты по введённым данным для самопроверки.

## Что изменилось в 1.3
- В редакторе виды сами рисуют схему по числам, введённым в «Корпус» (зелёный пунктир). В расчёт «По чертежу» схема не входит; «Сделать фигурами» превращает её в фигуры для правки.

## Что изменилось в 1.2
- Новая программа `sdp_ship`: данные судна в таблицах и чертёж из простых фигур в трёх видах; площади, центр парусности, осадка и размеры считаются по фигурам.
- Подложка-фото с привязкой двумя точками, подсказка контура по картинке и распознавание через Claude.
- Ядро не менялось; книга, сохранённая редактором, загружается ядром так же, как заполненная вручную.

## Что изменилось в 1.1
- Ядро запускается без данных и само ждёт их: НЕТ СУДНА → ЖДУ ДАТЧИКИ → ГОТОВ → УДЕРЖАНИЕ.
- Судно загружается командой `ship load`; загруженное судно — основа модели. Сменить судно можно только в ожидании.
- Имитатор запускается отдельно: `sim start <книга имитатора>`, своя книга `Данные_имитатора`.
- Из книги судна убран лист «Работа» (источник данных и параметры имитатора).
- Журнал включается параметром `--log файл.csv`.

## Проверка всего проекта одной командой
```
tools/ci_build.sh            # с редактором (нужен Qt 6)
tools/ci_build.sh --no-editor
```
Итог — в `test-out/итог.txt`, сценарии удержания и отказов — в `test-out/сценарий_*.txt`.

## Агенты в GitHub
1. Установить приложение Claude для GitHub на репозиторий SDP-Core-cpp.
2. Внести секрет `ANTHROPIC_API_KEY` (Settings → Secrets and variables → Actions).
3. Actions → «Агенты: задачи» → Run workflow (создаст метки).
4. Задача агенту: открыть задачу (issue) и поставить метку `агент:координатор`, `агент:тестировщик` или `агент:администратор`.
5. Свои предложения изменений агенты проверяют сами; изменение от агента — поставить метку `агент:проверка`.
Подробно — `SECURITY.md` и `.github/agents/README.md`.
