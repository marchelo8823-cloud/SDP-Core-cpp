# Запуск и проверка SDP-Core на Mac

Этот файл — постоянная инструкция по установке, сборке, запуску пульта, проверке записи сеанса и диагностике ошибок. Он обновляется вместе с изменениями проекта.

Рабочая папка на текущем компьютере:

```text
/Users/evgenijmarcenko/Downloads/sdpcore
```

> В первых проверках используйте только демонстрационное судно и имитатор. В этом режиме реальные датчики не читаются, а команды на настоящие движители не передаются.

## 1. Что должно быть установлено

На текущем Mac уже установлены Homebrew, CMake, компилятор и Qt 6. Для другого Mac потребуются:

- Xcode Command Line Tools;
- Homebrew;
- CMake;
- Qt 6 с Qt Quick и Qt Quick Controls;
- Python 3 для проверки CSV и части автоматических тестов.

Команды установки при необходимости:

```bash
xcode-select --install
brew install cmake qt python
```

Проверка доступности программ:

```bash
cmake --version
brew --prefix qt
python3 --version
```

На текущем Mac Qt находится в `/opt/homebrew/opt/qt`.

## 2. Быстрый запуск уже собранного пульта

Откройте **Терминал** и выполните:

```bash
cd /Users/evgenijmarcenko/Downloads/sdpcore

./build/hmi/sdp_hmi \
  --ship "$PWD/data/Данные_судна_пример.xlsx" \
  --sim "$PWD/tests/scenarios/имитатор_быстро.xlsx"
```

Должно открыться окно **«СДП — пульт оператора»**.

Проверьте верхнюю строку:

- отображается **«Демонстрационное судно»**;
- есть метка **«ИМИТАЦИЯ ×20»**;
- после небольшого ожидания состояние становится **«ГОТОВ»**.

Если сначала показано **«ЖДУ ДАТЧИКИ»**, немного подождите: имитатор должен передать курс и положение.

Чтобы завершить программу, закройте её окно или нажмите `Ctrl+C` в Терминале.

## 3. Обновление и пересборка проекта

Не запускайте обновление, сборку и тесты одновременно в разных окнах Терминала. Сначала дождитесь завершения каждой команды.

```bash
cd /Users/evgenijmarcenko/Downloads/sdpcore

git checkout main
git pull origin main

cmake -S . -B build \
  -DSDP_BUILD_HMI=ON \
  -DSDP_BUILD_EDITOR=ON \
  -DCMAKE_PREFIX_PATH="$(brew --prefix qt)"

cmake --build build -j
```

После сборки снова используйте команду из раздела 2.

Если нужна только консольная проверка книги судна без графического интерфейса:

```bash
cd /Users/evgenijmarcenko/Downloads/sdpcore
./build/sdp_run --check "$PWD/data/Данные_судна_пример.xlsx"
```

Исправная книга завершает проверку сообщением **«Книга в порядке»**. Предупреждения и значения по умолчанию при этом могут отображаться — это не ошибки.

## 4. Включение удержания позиции

На вкладке **«Главный»**, в панели **«Режим»**:

1. Нажмите **«Взять все движители»** один раз.
2. Нажмите **«Позиция»**.
3. Нажмите **«Позиция»** ещё раз в течение 3 секунд. Второе нажатие — обязательное подтверждение команды.

Ожидаемый результат:

- вверху появляется **«УДЕРЖАНИЕ»**;
- рядом указано **«удержание позиции»**;
- движители начинают выдавать упор;
- на плане видны судно, заданная точка и векторы воздействий.

### Сдвиг заданной точки

В панели **«Сдвиг точки»**:

1. Выберите шаг **«5 м»**.
2. Нажмите **«С ↑»**.
3. Заданная точка сместится на 5 м к северу.
4. Имитируемое судно должно начать перемещение к новой точке.

Остальные кнопки:

- **«← З»**, **«В →»**, **«Ю ↓»** — сдвиг точки;
- **«−1°»**, **«+1°»** — изменение курса, шаг можно выбрать в списке рядом;
- **«Точка = здесь»** — перенос заданной точки в текущее положение судна.

Для перехода в ожидание дважды нажмите **«Ожидание»**.

## 5. Основные вкладки для проверки

- **Главный** — план, курс, режим, сдвиг точки, среда, отклонение и мощность.
- **Опорные системы** — четыре группы карточек: положение (GNSS/LASER), курс (GYRO), качка (MRU) и ветер (WIND). Показаны источники решения, СКО положения, качество GNSS, отклонения курса, состояние и возраст данных каждого датчика. Метка **«В РЕШЕНИИ»** показывает, какой источник положения фактически использует оценщик.
- **Движители** — команды, обратная связь, упор, мощность и отказы.
- **Тренды** — окна 5, 15 и 60 минут; отклонение, курс, загрузка, ветер и внешнее возмущение.
- **Возможности** — полярная диаграмма предельного и рабочего ветра.
- **Анализ отказов** — анализ последствий отказов для выбранного класса.
- **Тревоги** — активные и квитированные сообщения.
- **Мощность** — текущая нагрузка и прогноз.
- **Настройки** — палитра, рабочее место, параметры управления и запись сеанса.

Палитры **«День»**, **«Сумерки»**, **«Ночь»** находятся на вкладке **«Настройки»**.

### Проверка отказа и восстановления датчика LASER

Проверка выполняется только с демонстрационным судном и имитатором:

1. Откройте вкладку **«Тревоги»**.
2. В поле **«Команда ядра (help — список)»** внизу экрана введите `sim off LASER` и нажмите Enter.
3. Откройте **«Опорные системы»** и подождите несколько секунд.

Ожидаемые признаки отказа:

- сводка показывает **«9 / 10 активны»** и красное **«НЕТ ДАННЫХ: 1»**;
- строка LASER становится красной и содержит **«Нет свежих показаний»**;
- источник решения положения меняется на **«GNSS1+GNSS2»**;
- GNSS1 и GNSS2 отмечены **«В РЕШЕНИИ»**.

Для восстановления вернитесь на **«Тревоги»**, введите `sim on LASER` в том же поле команды и нажмите Enter. Через несколько секунд на вкладке **«Опорные системы»** должны появиться:

- **«10 / 10 активны»** и **«ВСЕ В НОРМЕ»**;
- LASER без красного предупреждения и с меткой **«В РЕШЕНИИ»**;
- источник решения положения **«GNSS1+GNSS2+LASER»**.

Проверенные снимки отказа и восстановления: [отчёт](отчёты/проверка_отказа_laser.md).

## 6. Автоматическая запись сеанса

Откройте **«Настройки» → «Запись сеанса»**.

На экране отображаются:

- состояние **«Запись ведётся автоматически»**;
- имя текущего CSV;
- размер файла;
- фактическая папка;
- предупреждение, если выбранное место недоступно.

### Папка на флешке

1. Подключите флешку и создайте на ней пустую папку.
2. Нажмите **«Выбрать папку…»**.
3. Выберите созданную папку.
4. Убедитесь, что путь на экране изменился.
5. В Finder проверьте появление файла `сеанс_….csv`.

Выбор сохраняется для следующих запусков. При каждой смене папки создаётся новый файл; прежний CSV не перезаписывается.

Кнопка **«Внутренняя папка»** возвращает запись в штатный каталог приложения.

### Ручная выгрузка

1. Нажмите **«Выгрузить CSV»**.
2. Выберите место и имя копии.
3. Дождитесь сообщения **«Выгружено: …»**.

Выгрузка не останавливает автоматическую запись.

Проверка выгруженного файла в Терминале:

```bash
cd /Users/evgenijmarcenko/Downloads/sdpcore
python3 tools/sdp_report.py "/полный/путь/к/вашему/файлу.csv"
```

## 7. Проверка резервной записи

Для первой проверки безопаснее не извлекать флешку, а использовать временную папку на внутреннем диске:

1. Создайте в Finder папку `Проверка записи`.
2. Выберите её в настройках пульта.
3. Дождитесь появления CSV и нескольких секунд записи.
4. Переименуйте папку в Finder.

Примерно через секунду пульт должен:

- показать жёлтое предупреждение;
- отобразить **«РЕЗЕРВ: внутренняя папка»**;
- создать новый CSV на внутреннем диске;
- продолжить запись.

Фактический резервный путь показан на экране. Данные между старым и новым CSV не копируются.

Для возврата нажмите **«Внутренняя папка»** или повторно выберите пользовательскую папку. Автоматического возврата на появившуюся флешку нет.

## 8. Автоматические тесты

Закройте запущенный пульт перед проверкой. Не выполняйте одновременно `git pull`, сборку или изменение файлов проекта.

Запуск полного набора:

```bash
cd /Users/evgenijmarcenko/Downloads/sdpcore
ctest --test-dir build --output-on-failure
```

Ожидаемый итог на Mac:

```text
100% tests passed, 0 tests failed out of 47
```

На Linux в GitHub ожидается 46 тестов: проверка `hmi_locale` добавлена только на macOS. Полный прогон занимает примерно пять минут.

Повтор только упавших тестов:

```bash
ctest --test-dir build --rerun-failed --output-on-failure
```

Повтор одного теста, например проверки записи:

```bash
ctest --test-dir build -R '^hmi_recording_dir$' --output-on-failure
```

Отдельная проверка экрана **«Опорные системы»** во всех трёх палитрах:

```bash
ctest --test-dir build -R '^hmi_references$' --output-on-failure
```

Проверяются четыре группы, десять активных датчиков демонстрационного судна и снимки на 1366×768: `build/hmi_references_day.png`, `build/hmi_references_dusk.png`, `build/hmi_references_night.png`.

Журнал последнего прогона:

```text
/Users/evgenijmarcenko/Downloads/sdpcore/build/Testing/Temporary/LastTest.log
```

Открыть его в TextEdit:

```bash
open -a TextEdit /Users/evgenijmarcenko/Downloads/sdpcore/build/Testing/Temporary/LastTest.log
```

## 9. Если несколько HMI-тестов упали одновременно

Сначала посмотрите снимок `build/hmi_control.png` или откройте `LastTest.log`.

Если пульт показывает **«НЕТ СУДНА»**, остальные ошибки режима, прогноза и записи могут быть следствием: без загруженного судна удержание и CSV с данными невозможны.

В актуальной версии ключ `--ship` проверяется до открытия интерфейса. Если книгу не удалось загрузить, проверка сразу завершается с кодом **10** и выводит первопричину из журнала ядра. В этом случае не исправляйте вторичные ошибки режимов и записи: сохраните весь вывод именно этой первой ошибки.

Если в журнале значения вроде `0.7`, `29.5` или `0.5` названы «не числом», причина — русская числовая локаль Qt. Консольная проверка книги при этом могла проходить. В актуальной версии пульт и редактор судна используют для данных Excel, JSON и NMEA десятичную точку независимо от языка системы; язык интерфейса не меняется. Отдельная проверка на Mac:

```bash
ctest --test-dir build -R '^hmi_locale$' --output-on-failure
```

Выполните по очереди:

```bash
cd /Users/evgenijmarcenko/Downloads/sdpcore

./build/sdp_run --check "$PWD/data/Данные_судна_пример.xlsx"

cmake --build build -j

ctest --test-dir build --rerun-failed --output-on-failure
```

Если книга исправна и повторные тесты проходят, сохраните первоначальный `LastTest.log` для анализа условий первого запуска. Если ошибка повторяется, пришлите:

- полный вывод CTest;
- `LastTest.log`;
- снимок окна пульта или `build/hmi_control.png`.

## 10. Другие типичные проблемы

### `command not found: cmake`

```bash
brew install cmake
```

### CMake не находит Qt 6

```bash
brew install qt

cmake -S . -B build \
  -DSDP_BUILD_HMI=ON \
  -DSDP_BUILD_EDITOR=ON \
  -DCMAKE_PREFIX_PATH="$(brew --prefix qt)"
```

### Нет компилятора

```bash
xcode-select --install
```

### Пульт остаётся в состоянии «ЖДУ ДАТЧИКИ»

- проверьте метку **«ИМИТАЦИЯ»**;
- убедитесь, что команда запуска содержит и `--ship`, и `--sim`;
- закройте окно и повторите команду запуска полностью.

### Кнопка «Позиция» недоступна

- дождитесь состояния **«ГОТОВ»**;
- нажмите **«Взять все движители»**;
- нажмите **«Позиция»** два раза с подтверждением в течение 3 секунд.

### Предупреждения о шрифте DejaVu Sans в безэкранных тестах

Если тест завершился успешно, эти сообщения не являются ошибкой. Итог определяется строкой `Test Passed` и итоговым процентом CTest.

## 11. Что прислать после проверки

Если всё работает, достаточно написать, что проверено: запуск, удержание, сдвиг точки, тренды, выбор папки и резервная запись.

Если есть ошибка, пришлите:

1. команду, которую выполняли;
2. текст ошибки;
3. снимок экрана;
4. при сбое тестов — `LastTest.log`.

До отдельной проверки не подключайте проект к реальному судну, датчикам или контроллерам движителей.
