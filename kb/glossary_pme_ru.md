# Системы положения: форматы, отказы, проверки качества

## Форматы телеграмм Fanbeam (поддержаны в v0.22)
Fanbeam 5, Installation and commissioning guide, гл. 3.1. Скорость 9600, 8N1. В проекте канал «Лазерный радар»: sensor <ID> accept MDL,CEG17,PMDTG … и положение мишени sensor <ID> target <номер> <север> <восток>.
MDL Standard: «NN RRRR.RR BBB.BB» (номер мишени, дальность в метрах, пеленг в градусах), пример «01 1098.70 123.45». MDL + контрольная сумма: добавляется «CC», XOR символов 1…18 в шестнадцатеричном виде (пример из руководства: «01 1098.70 123.45 17»). CEGELEC Standard (ASCII 17): «RRRRRR BBBBBB N», дальность×10 и пеленг×1000, пример «010987 123450 1»; используется многими консолями Alstom/Converteam/GE/Navis/Beier. CEGELEC Legacy: пеленг×100 (5 цифр). NMEA-расширение $PMDTG,NN,RRRR.RR,BBB.BB,LLL,A,S,F,M,TTT*CC: уровень сигнала, точность, уверенность трекинга, угроза, режим, наклон. Двоичные форматы Kongsberg/Nautronix в проекте не разбираются ⚠.
Пеленг считается от носа по часовой; поправка нуля — sensor <ID> brg off <°>. Сила бликов: прямое солнце, дождь, туман ухудшают слежение.

## Форматы Artemis Mk IV (поддержаны в v0.22)
Periph port, гл. 11.2.3: ASCII-16 «DDDDDD AAAAA R», ASCII-17 «DDDDDD AAAAAA R», ASCII-22 «DDDDDD BBBB AAAAAA S». D — дальность×10 (6 цифр), A — азимут (×100 или ×1000; «*» — азимута нет), B — пеленг мобильной антенны×10, R — READY (1 — данные годны), S — статус 0…3. Азимут — направление от Fix-станции на мобильную от севера. В проекте: sensor <ID> accept ART17 (или ART22) и положение Fix-станции sensor <ID> ref <север> <восток>. READY=0 или статус 0 — нет захвата (данные не используются); статус 2 — мобильная станция связана с маяком, азимута нет ⚠ (положения не даёт). Радар судна и интерференционные зоны (зависят от высоты антенн) могут вызывать «дыры» по дальности.

## NMEA для GNSS (v0.22)
GGA, GLL, RMC — положение (как раньше); GNS — режим по созвездиям (N нет решения, A автономно, D дифф., P точное, R RTK fixed, F RTK float, E счисление); GST — реальные СКО широты/долготы: вместо заданного СКО используется большее из заданного и GST; GSA — тип решения (2D/3D) и PDOP/HDOP/VDOP (показ); ZDA — время UTC (показ); $PDPGGA / $DPGGA — отфильтрованное GGA для ДП. ROT гирокомпаса — скорость поворота (показ). VTG — скорость и курс над грунтом (показ).

## Проверки качества опорных систем (как в K-Pos / Converteam / GE)
Заморозка: одинаковые измерения подряд (по умолчанию 10) — система не используется. Предсказание (окно): измерение сравнивается с прогнозом модели, окно Узкое/Обычное/Широкое на систему (ref <ID> accept narrow|normal|wide). Медиана (три и более системы): режимы off / warn / reject (fusion median …). Дисперсия (повторяемость): СКО шума по вторым разностям последних отсчётов сравнивается с заявленным СКО; тревога POS_VARIANCE при превышении (fusion variance warn, fusion variance factor <k>). Веса: обычные, ручные 1–10 (ref <ID> weight …, fusion weights manual) или по повторяемости (fusion weights auto): вес = (СКО заявленное / max(СКО заявленное, повторяемость))² — только снижает вес шумной системы. Расхождение: предупреждение, если две системы расходятся больше предела (fusion diverge <м>); отбраковки нет. Режимы системы: enable, monitor (проверки идут, в решение не входит), mobile («мобильная» — не участвует в удержании, например маяк ROV; ставится как ref <ID> mode mobile), disable.

## Типичные характеристики и отказы
DGPS: ±1–3 м, потери от мультипути, созвездия, залипание («deadlock»), скачки до сотен метров, медленный дрейф, форматы интерфейса; лазерные системы (Fanbeam, CyScan): <0,5 м, дальность порядка 250 м, солнце/дождь/туман; гидроакустика (HiPAP): винтовой поток, косяки рыбы, шум; Artemis: радио, интерференция, потеря захвата, AGC; натянутый трос: ограничен глубиной и углом. Ни одна система не лучше при отсутствии проверок: нужна независимая сверка источников разной физики.
